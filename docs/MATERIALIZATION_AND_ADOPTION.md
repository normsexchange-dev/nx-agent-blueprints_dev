# Proposed materialization and adoption

Materialization is model-free and proposal-only. Inputs name an environment genesis record, destination environment, distinct new agent ID, optional parent identity, exact family owner/repository/tag/object/target/digest, optional specialization releases, creation time, adapter, and empty output directory.

The materializer verifies exact annotated release provenance, package hashes, genesis and communications compatibility, and distinct identity. It writes a proposed individual manifest and instructions while importing no credential, external permission, private instance memory, transcript, or reasoning. It activates no standing mission. Repeating the same inputs before local evolution is byte-identical.

For an existing agent, the comparison tool examines its pinned release, local state, and proposed release. It reports purpose, procedures, knowledge, boundaries, tools, evaluations, compatibility, privacy, new external-capability requirements, local divergence, and a three-way comparison. It never overwrites local files. The sovereign owner records one disposition: adopt, reject, defer, remain on current, fork, or create specialization. Adoption records preserve individual identity and history and are append-oriented.
