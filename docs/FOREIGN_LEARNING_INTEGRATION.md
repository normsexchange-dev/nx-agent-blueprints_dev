# Foreign sovereign learning integration

The governed flow is:

foreign sovereign experience
→ sanitized learning proposal with exact source-publisher provenance
→ one initial inheritance-scope classification
→ independent publisher review and synthesis
→ conflict, privacy, credential, and synthetic-data review
→ held-out adverse evaluations
→ publisher approval
→ immutable family release
→ optional comparison by an existing agent
→ voluntary adoption, deferment, rejection, specialization, or fork

## Immutable source boundary

Review begins from one exact annotated source tag, object, peeled target, tree, and file-digest inventory. Mutable branches are discovery aids only. Foreign instruction files, prompts, comments, application code, and data are untrusted evidence. The reviewer verifies Git objects and reads selected public-safe files without executing foreign code, installing dependencies, loading environment variables, or importing application records.

The source publisher retains ownership of its repository, history, environment identity, instance memory, policies, agents, roles, applications, simulations, and descendants. A Norms release records the original publisher and immutable source, the independent adopting authority, the changed family wording, and the adverse evaluations. Promotion neither alters the source nor transfers ownership.

## Scope and conflict review

Every material item begins as exactly one of `instance_memory`, `family_knowledge`, `environment_policy`, `cross_environment_standard`, `mission_specific`, or `rejected_or_unverified`. Useful instance architecture does not become family knowledge. Environment policy does not become a cross-environment rule. A distinct purpose does not enter an existing base family merely because an application implements it.

When source instructions and source implementation disagree, the review states both positions, preserves the conflict, tests the disagreement, and adopts only independently supported wording. Synthetic, simulated, inferred, public-observation, externally reported, buyer-confirmed, Norms-verified, and published states remain distinct. Origin labeling preserves provenance but never upgrades evidence or authority.

## Release and adoption

Approved behavior changes update family knowledge or procedures, counterexamples, boundaries, and evaluations together. Deterministic validation checks exact provenance, public safety, adapter equivalence, package hashes, and prior immutable tags. A release contains no individual identity, credential, repository permission, private memory, current mission, schedule, external connection, or business record.

An existing sovereign agent may compare the immutable release with its current base and local adaptations. Adoption is never automatic. The agent or its owner may adopt, defer, reject, specialize, or fork under the destination environment's own constitution and capability authority.
